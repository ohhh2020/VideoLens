# VideoLens 视频链接智能总结系统——需求分析文档

## 1. 引言

### 1.1 编写目的

本文档用于明确 VideoLens 视频链接智能总结系统的业务背景、用户需求、功能需求和非功能需求，为后续项目分析与设计、编码实现和现场演示提供依据。

### 1.2 项目背景

视频内容数量快速增长，用户观看长视频的时间成本高。传统做法是人工观看并整理摘要，效率低、主观性强。大模型和多模态理解技术的发展，使“自动理解视频并生成结构化总结”成为可能。

本项目的调研参考了视频多模态大模型领域的相关文献，包括：

- VideoChat3：视频 token 高效压缩与流式三态交互；
- Mage-VL：codec 原生稀疏 tokenization 与双系统门控；
- LLaVA-OneVision-2：codec-stream tokenization 与精确时间定位；
- Video-MTR、VITAL：长视频“稀疏概览 + 按需回看”的检索式理解；
- MiniCPM-V 4.6：端侧轻量多模态模型。

这些工作表明：视频理解的关键不是“把所有帧都塞进模型”，而是 **先做高效采样，再融合语音和画面信息**。本项目将该思想工程化为一个可演示的 Python 系统。

### 1.3 术语定义

| 术语 | 含义 |
|------|------|
| VLM | Vision-Language Model，视觉语言多模态大模型 |
| LLM | Large Language Model，大语言模型 |
| ASR | Automatic Speech Recognition，自动语音识别 |
| 关键帧 | 从视频中抽取的代表性画面 |
| 时间线 | 按时序组织的视频章节/事件列表 |
| OpenAI-compatible API | 兼容 OpenAI 接口协议的大模型服务 |

## 2. 用户与场景

### 2.1 目标用户

- 学生：快速理解网课、讲座、教学视频。
- 内容运营人员：快速获取视频内容、选题和复盘素材。
- 知识工作者：将会议录屏、产品讲解转化为文字纪要。
- 普通用户：希望在不完整观看视频的情况下了解核心内容。

### 2.2 典型使用场景

1. 用户粘贴 B 站教程视频链接，系统生成章节摘要和时间线。
2. 用户输入会议录屏直链，系统输出逐句转写和会议要点。
3. 用户选择本地 MP4，系统生成画面描述与文字总结。
4. 现场演示场景：输入短视频链接，数分钟内展示完整总结结果。

## 3. 项目目标与实际应用价值

### 3.1 业务目标

- 降低视频信息获取时间：用户无需完整观看即可获得摘要。
- 提高视频内容利用效率：输出可检索、可归档的文本和结构化数据。
- 展示 AI 与多模态技术在真实场景中的落地能力。

### 3.2 实际应用价值

- **时间价值**：10 分钟视频可在数分钟内生成可读摘要。
- **知识管理价值**：将非结构化视频转化为结构化文字，方便搜索和整理。
- **教育价值**：为网课学习提供快速预习和复习材料。
- **无障碍价值**：为听障用户提供文字稿和画面描述。
- **工程示范价值**：形成“下载—转写—视觉理解—总结—展示”的完整 Python 项目。

## 4. 范围

### 4.1 项目包含

- 视频链接解析与下载；
- 音频提取与语音转写；
- 关键帧抽取；
- 关键帧视觉理解；
- 文本与视觉信息融合总结；
- Web 展示与结果导出；
- 命令行运行方式。

### 4.2 项目不包含

- 不训练自有视频多模态大模型；
- 不实现视频剪辑、封面生成等编辑功能；
- 不提供公开 SaaS 服务；
- 不对版权受限视频进行批量爬取或分发。

## 5. 功能需求

### FR-1 视频输入

- 系统支持视频 URL 输入。
- 支持 `yt-dlp` 可解析的平台链接、MP4 直链和本地视频文件。
- 输入为空或无法解析时给出明确错误提示。

### FR-2 视频元数据获取

- 获取视频标题、时长、原始链接和缩略图信息。
- 下载失败时给出可读的错误原因。

### FR-3 视频下载

- 自动选择可用的 MP4 格式。
- 支持 cookie 文件路径配置。
- 支持下载进度提示。
- 下载文件保存在 `data/videos`。

### FR-4 音频提取

- 使用 FFmpeg 从视频中提取 16kHz 单声道 WAV 音频。
- 音频提取失败不应阻断画面理解和总结流程。

### FR-5 语音转写

- 使用本地 `faster-whisper` 转写音频。
- 输出包含开始时间、结束时间和文本的逐句片段。
- 长视频应使用 VAD 过滤静音，降低无效处理时间。

### FR-6 关键帧抽取

- 按固定时间间隔抽取均匀采样帧。
- 使用帧间差异检测场景变化，补充代表性画面。
- 控制最大关键帧数量，避免视觉 token 爆炸。
- 关键帧以 JPEG 保存，并记录时间戳。

### FR-7 视觉理解

- 在配置 API Key 的情况下，调用 VLM 描述关键帧内容。
- 输出画面主体、动作、场景和潜在事件。
- 未配置 API 或调用失败时，跳过视觉理解，系统仍可运行。

### FR-8 智能总结

- 融合语音转写文本和画面描述。
- 输出以下内容：
  - 一句话总结；
  - 核心要点；
  - 时间线；
  - 关键词；
  - 标签；
  - 适合人群。
- 未配置 LLM API 时，使用规则引擎生成基础总结。

### FR-9 Web 界面

- 提供链接输入框和分析按钮。
- 展示视频预览、总结报告、时间线、转写文本和关键帧画廊。
- 展示分析过程中的阶段提示。

### FR-10 结果导出

- 输出目录包含：
  - `result.json`：结构化结果；
  - `summary.md`：Markdown 总结；
  - `transcript.json`：语音转写；
  - `keyframes/`：关键帧图片；
  - `captions.json`：画面描述。

## 6. 非功能需求

### NFR-1 性能

- 3–8 分钟短视频在常规 PC 上应在 3–6 分钟内完成分析。
- 语音转写采用本地模型，避免上传音频导致的隐私和网络开销。
- 关键帧数量默认不超过 20，控制 API 调用成本。

### NFR-2 易用性

- 用户只需要输入链接即可完成分析。
- 错误信息应面向普通用户，避免只输出堆栈信息。
- 提供 Web 界面和命令行两种入口。

### NFR-3 可扩展性

- 语音、视觉、总结模块解耦，便于替换模型或后端。
- 配置集中在 `.env`，不硬编码模型名和路径。

### NFR-4 隐私与安全

- 本地音频转写默认不向第三方上传音频。
- API Key 通过环境变量读取，不写入代码和结果文件。

### NFR-5 可维护性

- 代码按模块划分，单一职责。
- 关键流程有日志和阶段回调。
- 输出使用 JSON/Markdown，便于人工检查。

## 7. 外部接口

| 外部系统 | 用途 | 说明 |
|----------|------|------|
| yt-dlp | 视频解析与下载 | 支持多平台 |
| FFmpeg | 音视频处理 | 提取音频 |
| faster-whisper | 本地语音转写 | 不依赖云端语音服务 |
| OpenAI-compatible API | 视觉理解与文本总结 | 可替换任意兼容模型 |
| Gradio | Web 界面 | 便于现场演示 |

## 8. 数据需求

### 8.1 输入数据

- 视频 URL：字符串。
- 可选配置：API Key、模型名、帧间隔、最大帧数。

### 8.2 中间数据

- 视频文件：MP4。
- 音频文件：16kHz WAV。
- 转写片段：JSON。
- 关键帧：JPEG。
- 画面描述：JSON。

### 8.3 输出数据

- 结构化总结：JSON。
- 可读报告：Markdown。

## 9. 验收标准

1. 输入一个可下载视频链接，系统能完成下载。
2. 能输出包含时间戳的语音转写。
3. 能输出关键帧图片，且数量不超过配置上限。
4. 配置 VLM/LLM 后，能输出画面描述和智能总结。
5. 未配置 API 时，系统仍能输出转写和规则总结。
6. Web 界面能完成从链接输入到结果展示的完整流程。
7. 输出目录中包含 `result.json` 和 `summary.md`。

## 10. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 视频站点反爬或需要登录 | 下载失败 | 支持 cookie 文件；准备本地 MP4 备份 |
| 长视频转写耗时 | 演示超时 | 默认限制演示视频时长；提供进度提示 |
| API 调用失败或未配置 | 视觉总结缺失 | 设计无 API 回退路径 |
| 现场网络不稳定 | 下载失败 | 提前缓存演示视频 |
| 模型输出格式不稳定 | 无法解析 JSON | 增加容错解析和文本回退 |
