# 前台控制台与网页服务菜单

在已激活 Conda 环境的 Git Bash 中执行：

```bash
bash scripts/start_web.sh --port 8000
```

服务保持在可见终端，最底部单独保留一行黄色 `<< ` 输入标识，输入指令后按 Enter。日志在上方滚动，不在每条日志之间打印提示符，也不清除正常日志刷新时正在输入的内容。窗口大小变化后会调整输入行位置；关闭后恢复 Bash 的普通滚动区域。重定向到文件或管道时不显示输入提示符。

固定输入行需要终端支持 ANSI/VT 光标控制。程序会在 Windows 控制台上启用并核验 VT，或验证 mintty/MSYS 的真实 PTY 管道；不会只凭 `MSYSTEM`、`TERM` 环境变量启用。普通输出面板或重定向管道使用纯文本，不输出颜色、光标控制码或提示符；不支持清屏时直接提示，且不写入日志文件。

修改控制台自身的渲染或初始化代码后，需要 `stop` / Ctrl+C 完整退出，再重新执行启动脚本。`restart` 和网页重启菜单只重启后端子服务，保留当前控制台父进程。

| 指令 | 作用 |
| --- | --- |
| `help`、`?`、`帮助` | 查看指令 |
| `status`、`状态` | 服务状态、进程号、任务数与三个模型的实际设备 |
| `clear`、`清屏` | 清空终端屏幕与滚动内容，不改写日志 |
| `stop`、`关闭`、`退出`、`exit`、`quit` | 等待任务与请求结束，正常关闭 |
| `restart`、`重启` | 等旧服务结束，再加载代码和配置，创建新日志 |

Ctrl+C 也可正常关闭。未知指令只显示提示，不作为系统命令执行。长任务执行期间关闭或重启会等待推理收尾。

## 网页菜单

右上角菜单提供重启与关闭，复用同一控制台流程。操作时禁用按钮防重复提交，检测到新进程就绪后才提示重启成功。关闭后页面可保留已显示内容，但不能继续处理请求；再次使用须执行启动脚本。

## 启动参数

| 参数 | 含义 |
| --- | --- |
| `--host 127.0.0.1` | 默认本机监听，也支持 `localhost`、`::1` |
| `--port 8000` | 设置端口 |
| `--reload` | 开发时监视前后端变更并正常重启 |
| `--help` | 查看帮助 |

`start.bat`、`python -m backend.web.main` 同样进入前台控制台，参数只与网页启动有关。

本机 IPC 支持程序化发送相同指令。`state/console-端口.json` 包含随机认证信息，不要分享；正常退出后删除。Windows 管道先检查可读字节再读取，避免阻塞读取与原生模型库初始化互锁。

输出规则见[日志文件与格式](日志文件与格式.md)。

## Windows Terminal / Git Bash 输入兼容

原生Windows控制台改为非阻塞逐键读取，不再在原生输入句柄上挂起同步 `ReadFile`；管道输入继续先检查可读字节。输出每次渲染前重新核验VT能力，若共享模式被库或子进程改动则恢复；无法恢复时退为纯文本，避免打印 `←[` 控制码。原生控制台优先直接查询窗口尺寸，避免反复调用MSYS `stty`。

Conda的 `Library/ssl/cacert.pem` 提示表示当前进程已选择有效CA证书，HTTPS校验仍开启；它与后面的终端光标码属于两个独立问题。

此次修复涉及父控制台，必须完整退出旧启动脚本再开启才会加载。只通过网页或 `restart` 重启后端子进程不能替换旧父控制台代码。旧窗口的历史乱码不会因代码修改自动消失。
