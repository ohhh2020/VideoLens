# 完整性升级验收记录

验收日期：2026-10-31。分析版本：`integrity-v2`，数据库 schema 8。代码使用现有 Conda Python 3.13；FFmpeg / FFprobe 使用用户配置。未进行旧视频批量升级，也未推送 GitHub。

## 已实现的七阶段

1. 统一语音、画面、OCR 子证据，保留原文、来源、实际采样时间和视频编码范围；最长 15 秒窗口保留尾段。
2. 全部切片进入按预算分批的递归摘要树；缺失或失败不能标记完成，完整事实及关联证据可查。
3. 默认最高可用 1080p，640px 低成本扫描与 1920px 证据帧分离；局部变化复查，原像素裁图。
4. 独立 OCR 原始结果与预算，JSON 截断拆小重试，保留代码缩进、表格和不确定性。
5. 局部检索、全局章节遍历、最多两轮补检索；新版可有限补取证，旧视频只读取现有证据。
6. 按任务预算、实际 usage / finish_reason、最多两次普通文本续写，仍未完成明确提示。
7. GPU 自适应 batch 与 OOM 缩批、统一云端并发和退避、8 MiB 分块续传、8 GiB / 两小时边界与磁盘余量保护。

参数、流程、目录和恢复方法见[完整性分析与资源配置](完整性分析与资源配置.md)。三个本地模型仍为 BGE-M3、faster-whisper-small、SigLIP2；没有增加本地 OCR、视觉或文本生成模型。

## 三类 10 分钟受控样本：真实模型调用

样本由 Windows TTS、固定代码/表格幻灯片和 FFmpeg 生成，每类 600.064 秒、1920×1080。稀疏 3 页、中等 12 页、密集 60 页；分别有 6、24、120 个预先确定的数值事实。它们是**受控合成视频，不是自然视频人工标注集**。

测试使用实际三个 CUDA 模型和现有独立云端配置。期间网页服务也在运行，因此耗时与设备显存峰值受本机并发负载影响，不作为独占性能基准。

| 样本 | 有效切片覆盖 | 原始证据 | 数值事实索引命中 | 本轮分析时间 |
| --- | ---: | ---: | ---: | --- |
| 稀疏 | 21/21，100% | 229 | 6/6 | 首次 131.82 秒 |
| 中等 | 24/24，100% | 410 | 24/24 | 首轮 43.33 秒因 OCR 格式失败；修复后手动恢复 113.46 秒 |
| 密集 | 30/30，100% | 955 | 120/120 | 首次报告完成 806.70 秒 |

数值命中统计检查完整事实索引是否出现标签数值；不等同于逐条检查键值归属、时间、因果、否定和所有语义事实。最终概览允许压缩，因此不能拿概览中的数值个数替代完整事实索引覆盖。

报告完成时服务商返回的使用量如下，尚不包含随后全局问答的全部请求：

| 样本 | 请求次数 | 输入 tokens | 输出 tokens |
| --- | ---: | ---: | ---: |
| 稀疏 | 53 | 91,009 | 34,123 |
| 中等 | 127（含1次失败） | 197,449 | 32,180 |
| 密集 | 532 | 880,644 | 259,603 |

这里包含开发验证时的实际重试及当时提示词版本。后续修复了摘要短 ID 映射、同切片重复文字合并等，但未重新冷跑全部样本，不能由此承诺固定加速。价格未配置，未编造费用；未返回 usage 的失败请求可能仍由服务商计费。

稀疏样本观测设备已用峰值约 3.66 GiB、该进程 PyTorch 分配峰值约 1.84 GiB。前者包含其他进程，后者不包含 CTranslate2，均不能称为本服务独占总显存峰值。

完整原始材料位于运行目录 `tests/integrity-v2/samples/`、`benchmark-final/`、`numeric-recall.json`。数据库与原始账本保留每次请求、摘要树和覆盖清单。

### 全局问答实测

稀疏与中等样本全局问答完成。密集样本首次问答发现：直接重复读取955个底层摘要会让分批输出膨胀，触发“压缩未收敛”；报告仍保留，没有伪报问答成功。修复后改为遍历全部叶节点，按切片聚合全部事实，只合并逐字相同的重复项，逐事实保存原始证据来源映射。修复没有重跑视频、OCR或报告。

密集样本真实复验通过：最终问答使用30条汇集后的章节证据，输出6124字符、30条引用，最终调用输入5385 / 输出3922 tokens，`finish_reason=stop`，未截断。上述 tokens 是最终生成调用，不包含分批阅读；全部请求在账本中可查。`benchmark-final/results.json` 保存最终密集样本问答，`results-before-fact-merge.json` 保留修复前错误和中等样本结果。

## 兼容旧链路对照

同一个密集受控样本通过隔离旧链路完成，首次分析 155.02 秒。旧版最终概览包含 75/120 个标签数值；新版最终概览约 59 个，完整事实索引为 120/120。**比较口径不同，不能据此声称新版最终概览召回更高**；新版收益是全部切片的完整证据与事实索引可追溯，而非强迫概览列出所有数字。

基线结果位于运行目录 `tests/integrity-v2/benchmark-baseline/results.json`。本轮没有完成自然视频的逐条人工事实评审，**“语义召回至少90%、错误事实数不高于基线”仍是待验收项**，不能以数值精确匹配代替。

## 验收边界

有限抽帧不保证瞬时信息全部捕获；静帧不能证明连续动作。局部阈值仍需要更多自然视频标注集校准。完整性优先的密集视频调用量明显增加，应先在设置中确认资源预算。100% 切片处理覆盖单独展示，不表述为100%语义信息召回。

用户原有视频、报告、会话和记忆不自动重算。测试创建的会话/视频在验收结束后清理；受控基准数据库保存在独立 tests 目录，不混入用户视频库。
