# 知影开发手册

这份文档面向刚接触编程的读者。可以先完成使用手册中的一次视频分析，再按本手册阅读源码；这样每个模块都能对应到一个已见过的行为。

## 1. 理解运行环境

Python 是程序使用的语言，Miniconda 负责把不同项目的 Python 与依赖隔离。`VideoLens` 是这个项目的环境名。`conda run --no-capture-output -n VideoLens ...` 表示“使用此环境运行后面的命令”，不会依赖当前终端是否已经激活环境。

`pyproject.toml` 描述项目名称、支持的 Python 版本、依赖和命令行入口。执行 `pip install -e .[heavy,dev]` 时，`-e` 表示可编辑安装：修改 `src/videolens` 后直接生效，无需每次重装；`heavy` 包含真实模型依赖，`dev` 包含 pytest 和 Ruff 等开发工具。

`requirements-lock.txt` 固定本次 Windows x64、Python 3.13.16、PyTorch CPU 基线的实际版本。需要复现时先 `pip install -r requirements-lock.txt`，再 `pip install --no-deps -e .`。此清单不包含 editable 的个人绝对路径，也不把 Windows CPU 结果冒充其他平台或 CUDA 兼容性证明。

```powershell
conda run --no-capture-output -n VideoLens python --version
conda run --no-capture-output -n VideoLens python -m pip install -e ".[heavy,dev]"
conda run --no-capture-output -n VideoLens python -m videolens --help
```

Windows Python、终端与文本文件均使用 UTF-8。原始 `.docx`、视频、音频、图片和模型属于二进制文件，不适用文本编码转换。`.editorconfig` 与 `.gitattributes` 统一新文件格式，脚本设置 `PYTHONUTF8=1` 和 `PYTHONIOENCODING=utf-8`。

## 2. 项目目录

```text
VideoLens/
├─ README.md                     用户入口
├─ pyproject.toml                包信息、依赖、测试和检查设置
├─ environment.yml              Conda 新环境说明
├─ config.example.json          可公开的配置示例
├─ config.local.json            个人配置，Git 忽略
├─ 一键配置环境.cmd / 一键启动.cmd / 一键测试.cmd
├─ scripts/                     环境部署、启动、样本与真实推理验证
├─ src/videolens/
│  ├─ config.py                 配置校验、路径、密钥引用
│  ├─ store.py                  SQLite 存储和事务
│  ├─ service.py                视频业务和后台任务编排
│  ├─ media.py                  下载、探测、字幕、切片和关键帧
│  ├─ models.py                 ASR、向量、文本与视觉模型统一入口
│  ├─ retrieval.py              关键词、Chroma 索引、RRF 融合
│  ├─ generation.py             上下文预算、结构化生成、引用校验
│  ├─ api.py                    HTTP API、认证、限流与 SSE
│  ├─ ui.py                     Gradio 网页
│  ├─ cli.py / __main__.py      命令行入口
│  ├─ bootstrap.py              模型与 llama.cpp 安装、进程管理
│  └─ errors.py                 业务错误和任务控制信号
├─ tests/                       离线、媒体与 API 等自动化测试
├─ docs/                        计划、使用、开发、API、测试和来源文档
├─ data/                        业务数据与验证结果，Git 忽略
├─ models/                      固定版本模型缓存，Git 忽略
└─ runtime/                     llama.cpp、日志与进程身份，Git 忽略
```

`service.py` 把各模块串起来，但网页和命令行不直接拼 SQL 或操作 Chroma。这样同一视频无论从哪种入口提交，处理逻辑都相同。读具体函数时参考 [架构与代码导读](架构与代码导读.md)。

## 3. 本地 Git 的基本用法

Git 把代码变化记录为提交。工作目录是你正在编辑的文件，暂存区是准备纳入下一次提交的改动，提交是一个可以回溯的快照。

```powershell
# 查看哪些文件发生变化。
git status --short

# 查看尚未暂存的修改内容。
git diff

# 只添加自己确认过的源码/文档；示例按真实修改调整。
git add src/videolens/media.py docs/开发手册.md
git diff --cached
git commit -m "改进字幕时间对齐并补充说明"

# 查看最近的项目快照。
git log --oneline -10
```

提交前确认没有 API Key、令牌、私人视频、数据库或模型。`.gitignore` 已排除常用运行目录，但不能代替查看 `git diff --cached`。项目使用本地 `main` 分支；没有自动创建或推送 GitHub 仓库。

回滚前先保存尚未提交的工作。对已经提交的某次逻辑变更，优先使用 `git revert <提交号>` 生成反向提交，保留历史。不要在不了解后果时运行 `git reset --hard` 或递归清空目录。

## 4. 添加或修改功能

### 增加一个设置

先在 `config.Settings` 中定义类型、默认值和范围，再决定是否能通过网页更新。影响产物的参数会进入配置指纹，避免恢复时混用旧算法结果。读取设置使用 `load_settings`，不要在多个模块写死路径、端口、模型或密钥。

`config.local.json` 是配置持久化文件；`config.example.json` 只是示例，程序不会自动把它当作个人配置。通过 `--config` 或 `VIDEOLENS_CONFIG` 可以选择另一份 JSON；数据路径相对所选 JSON 解析。

### 增加模型供应商

优先接入现有 OpenAI 兼容适配器。文本模型输出 Chat Completions 内容，视觉模型接受文字与 `image_url`。如果供应商协议不同，在 `models.py` 新建独立适配方法，保持生成、流式输出、超时和取消行为一致。

不要把 API Key 放在配置类或日志中。使用 `SecretStore` 保存凭据，再让 Provider 保存 `key_ref`。需要新增请求参数时，同时检查云端关闭条件、超时、流结束判断及错误日志中是否会泄露请求内容。

### 增加处理阶段

阶段实现应接收中断检查回调，在合适边界调用它。一个阶段完成后才写“完成”检查点；中途崩溃不能留下看似完成的记录。阶段写入必须能重试而不复制切片或向量。新的暂存文件应放在受管理临时目录，并纳入成功/失败清理规则。

### 修改检索

在 `IndexManager` 中处理索引版本，在 `fuse_rankings` 中处理排序。不直接相加不同模型的原始相似度：两种向量模型的数值尺度不同。修改 RRF 权重时，增加能够验证相关候选顺序的测试，而不仅断言函数被调用。

### 修改网页或 CLI

先增加或修改 API，再让网页与 CLI 调用该 API。网页显示模型输出时使用经过清理的 Markdown/文本，生成链接时只使用已经验证的视频和帧 ID。不要把后端密钥写入 JavaScript、本地存储或下载配置。

## 5. 测试与调试顺序

1. **语法与静态检查：**`python -m compileall -q src scripts`、`python -m ruff check src tests scripts`。
2. **离线测试：**`python -m pytest -q -m "not real_model and not cloud"`，覆盖业务规则和故障恢复。
3. **媒体集成：**安装 FFmpeg 后执行媒体测试，验证中文路径、字幕、音轨、帧时间与实际编码产物。
4. **本地真实模型：**先 `bootstrap verify-models`，再运行 `scripts/verify_real_models.py`；完整性校验和真实推理分开判断。
5. **界面与完整流程：**启动服务，完成导入、分析、检索、追问、时间定位、导出、重启读取历史。
6. **云端与性能：**使用实际模型服务与真实视频，记录硬件、模型版本、每阶段时间和失败原因。

单元测试中可以用替身模拟网络，验证超时、断流和错误分支，但这些结果只能称为协议/业务测试；不能用于宣称云端实际调用、GPU 推理或 ASR 准确率已经通过。

发生失败时，先从错误码、当前阶段和输入条件缩小范围。一次只改变一个因素，例如先固定 CPU 模式确认流程，再测试 CUDA；先使用带字幕短视频确认媒体链路，再测试无字幕转写。

## 6. 版本与兼容性

模型固定 revision 保存在 `bootstrap.MODEL_SPECS`，每次部署记录本地 `model-manifest.json`。升级模型时应更新 revision、重新校验文件，并重建对应向量索引。不同模型或不同向量维数不能复用同一个索引集合。

llama.cpp 发行包固定版本、直链和官方 SHA-256；安装不依赖实时 GitHub API。自定义包也必须提供哈希。可执行文件 `--version` 成功只证明能加载运行库，实际生成仍需 completion 测试。

当前数据库使用 `PRAGMA user_version=1`。未来变更数据结构时，应添加显式迁移步骤并先备份，不能仅修改建表 SQL 假设已有数据库会自动变更。SQLite 和 Chroma 不支持本项目所需的跨库联合事务，因此索引采用版本构建后切换。

首版 Windows 完整使用链路之外，Linux 需要自行提供 FFmpeg 和对应 llama-server，使用可用的密钥存储后端，替换 `.cmd` 启动方式，并重新验证路径、子进程和模型依赖。Windows 测试报告不能作为 Linux 已通过证明。
