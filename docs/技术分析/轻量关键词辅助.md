# 轻量关键词辅助与速度边界

## 理论判断

关键词能辅助模型优先阅读主题、型号、条件等相关原句，尤其在报告输入预算不足时有用。它不能恢复未采样画面、纠正所有转写/OCR错误，也不能替代对比较主体、百分比方向和因果关系的检查。关键词越多并不自动意味着报告更准确。

本项目原有 jieba 分词及词频/逆文档频率式评分。增加一个独立神经网络模型或额外云端关键词请求，会新增推理、模型内存或网络等待；KeyBERT 若额外编码候选短语，也会增加 BGE 工作量。考虑速度优先及只保留三个必需本地模型的要求，本次选用替换原评分的轻量统计模型，保留 BGE-M3、faster-whisper-small、SigLIP2 的既有部署边界。

| 方案 | 新增主要开销 | 本次选择 |
| --- | --- | --- |
| 额外云端提取关键词 | 网络等待与额外请求 | 不启用 |
| 新增本地神经关键词模型 | 权重加载、推理与显存/内存 | 不部署 |
| KeyBERT 候选短语重新编码 | BGE 编码与 GPU 竞争 | 不增加编码 |
| TF-IDF + 有界 TextRank | 原有分词加轻量 CPU 共现图计算 | 已实现实验开关，默认关闭 |

## 实现

`backend/analysis/keywords.py` 的实验模型使用一次分词结果进行统计与共现图排序，算法标记为 `tfidf-textrank-v1`。**当前默认 `integrity.keyword_assist: false`，继续使用既有 `tfidf-v1` 评分。** 实测没有证明开启后云端报告不降速，因此不自动启用。

- 保留 `i5-13600KF`、`5600XT`、`DDR4-3200`、`CUDA12.8` 等完整型号或版本，避免被切成无关联碎片。
- 完全相同的 OCR/字幕在关键词统计时只计算一次；原始证据及全部时间关联继续保存。
- 过滤常见口头语及点赞、关注等泛用词；这些词仅不参与关键词评分，不从原始证据删除。
- 共现图最多 128 个候选词、4096 条无向边、8 次迭代；长输入的扫描锚点分散至全文。全文统计不因此截掉证据正文。
- 最多输出 24 个关键词，主体仍由 TF-IDF 分数决定，共现关系及完整型号只作辅助。
- ASCII 型号匹配检查边界，`A1` 不为 `A10`、`BA1` 或 `A1-Pro` 加分。

关键词在本地用于选择已有完整证据，不作为独立事实追加到云端提示词。不增加抽帧、OCR裁图、章节摘要、云端关键词请求或 BGE 编码；原始证据仍全部参与现有索引。

实验开启时，数字、否定、步骤、比较关系及时间/来源保底继续发挥作用。对同一单元中不同数字做小幅、有上限的加权，防止只反复提及主题的短句挤掉具体数据；不为全部数字设置无限优先级。实验关闭时保持原有关键词、匹配及事实评分，不运行共现图。

## 为速度做的配套改动

每份报告对同一标题只召回一次偏好记忆，输入预算的多次试算复用固定前缀，避免反复编码同一个记忆查询。该缓存仅在一份报告内存在，下一份报告仍读取当前记忆。

在固定 JSON 消息结构下，预算试算按新增单元计算双层 JSON 转义后的字节成本，避免每加入一个单元就重新序列化整份上下文。完成选择后仍对完整消息核验一次；当前预算单位沿用项目的保守 UTF-8 字节估算，不能将其与服务商真实 tokens 混为一谈。通用调用仍保留全量预算计算方式。

报告的输入/输出预算和抽帧策略保持现有设置。关键词计算并非物理上的零耗时，端到端云端生成也会波动；必须同时检查本地打包耗时、实际云端输出量和报告生成时间，不能只看模型名称或 GPU 利用率。

## 存放与验证

新分析的 `data/analysis-runs/<run_id>/evidence.sqlite3` 中：

- `results.report_keywords`：入选关键词。
- `results.report_selection.keyword_model`：本次使用的关键词算法。
- `results.report_selection.evidence_scoring_ms`：完整单元构造与关键词评分耗时，包含首次分词初始化时的开销，不能视为纯 TextRank 耗时。
- `results.report_provenance`：入选及遗漏单元、所有来源与出现时间。

旧报告不会自动重算。修改后由用户通过现有前台控制台正常重启加载代码，新分析默认使用预算与记忆召回的性能修复，不自动运行关键词实验。

确需自行试验时，可将 `configs/app_config.yaml` 的 `integrity.keyword_assist` 改为 `true`，正常重启后再创建新分析。该开关属于参数快照，旧任务按已接受的快照继续执行；已完成视频仍复用原报告。**开启不代表保证更快或更准，本次不建议为日常使用开启。**

在已激活 Conda 的 Git Bash 中运行回归：

```bash
python tests/run_all.py -k keywords
python tests/run_all.py -k optimized_analysis
python tests/run_all.py -k preference_memory
```

`scripts/benchmark_keywords.py` 只读重放已有分析证据。需要提供改动前 `packing.py` 副本、一个或多个分析 run_id 和源码目录外的输出路径；默认不联网，仅显式 `--cloud` 才会调用已配置的文本模型并产生用量。`--current-prompt` 让两组使用相同的当前提示词，避免把提示词不同误算成关键词算法的收益；`--candidate-mode default` 验证最终默认配置，默认的 `experiment` 比较实验模型。

本次测试与试验回退见[关键词辅助验收](../更新日志/2026-11-03关键词辅助验收.md)。自动统计的型号/数字标记数量、切片关联数均不等于最终事实准确率或人工召回率。
