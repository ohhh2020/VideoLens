# 故障排查

先记录出现错误的阶段、界面提示与相关命令的退出码，再按下表处理。不要直接删除整个 Conda 环境或整个 `data/` 目录；这会丢失可用于恢复的状态。

## 1. 环境和编码

| 现象 | 原因与处理 |
|---|---|
| 找不到 `conda` | 在 Miniconda Prompt 运行；或把 `CONDA_EXE` 设为真实 `conda.exe` 路径。脚本优先查已注册命令，不假定安装盘符。 |
| 找不到 `VideoLens` | 先运行配置脚本。使用 `conda env list` 核对，不要把命令中的环境名改成 `base`。 |
| Python 3.13 无对应依赖轮子 | 先确认是版本兼容而非网络错误；配置脚本有 Python 3.12 兼容方案，并保留原环境导出清单。 |
| 出现 GBK/UnicodeDecodeError | 设置 `PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8`，重新打开终端；三个 `.cmd` 入口已处理。 |
| PowerShell 中文脚本乱码 | 使用 `.cmd` 入口或 PowerShell 7；Windows PowerShell 5.1 需要 `Get-Content -Encoding UTF8` 后执行。 |
| 安装网络超时 | 检查代理、DNS和剩余空间后重跑。首次安装与模型下载需网络；运行离线单元测试无需下载模型。 |
| Conda FFmpeg post-link 失败 | 脚本只尝试一次 Conda 事务，失败后采用官网推荐的固定 Gyan 构建；手动可执行 `python -m videolens.bootstrap ffmpeg`。 |
| Conda 回滚后提示不是环境 | 检查 `conda-meta/history` 是否被回滚删除。仅能恢复安装前保存的原文件，不应伪造历史；配置脚本对该文件做原始字节备份。 |

环境备份位于 `data/environment-backups/`。正常配置结束时会写 `requirements-installed.txt`，列出本机实际安装版本。部署失败时查该阶段输出；不能根据已有旧清单断言本次安装通过。

## 2. FFmpeg 与视频

```powershell
conda run --no-capture-output -n VideoLens python scripts/smoke_environment.py
conda run --no-capture-output -n VideoLens python -m videolens.bootstrap ffmpeg
```

冒烟检查会实际生成短音频，再用 FFprobe 验证采样率和声道。它会读取 `config.local.json` 中的 `ffmpeg` 与 `ffprobe` 路径，因此静态构建不需要加入系统 PATH。

“无法解码”时先用普通播放器检查原视频。扩展名为 `.mp4` 并不保证内部数据完整。下载到 HTML 错误页、零字节文件或缺失关键帧的视频应作为输入失败处理。

没有转录时，先确认视频确实有音轨和可听人声，再检查字幕是否为空、ASR 模型是否已安装。静音、纯音乐或背景噪音可能没有有效转录。字幕时间错位时检查是否为另一版本视频的字幕。

关键帧不足通常来自静态画面去重。源视频低于 720p 时不会插值放大；图片超过目标字节大小会记录偏差，应该结合实际可读性判断。

## 3. 模型下载和显卡

```powershell
conda run --no-capture-output -n VideoLens python -m videolens.bootstrap verify-models
conda run --no-capture-output -n VideoLens python -m videolens.bootstrap models --names asr,text,image,local
```

下载结束但缺少权重文件不能算成功。模型清单必须包含 `.bin`、`.safetensors` 或 `.gguf` 权重，并在实际加载时验证。ASR、BGE 和 SigLIP 的配置文件下载成功并不等于模型可用。

若出现哈希不匹配，应保留错误信息，确认代理没有替换下载内容，再重新下载对应损坏文件。不要把期望哈希改成错误文件的哈希来绕过校验。

显卡存在但推理失败时，应分别检查：

- **PyTorch：**`torch.cuda.is_available()` 仅是初步探测，仍需做 BGE/SigLIP 实际推理。
- **CTranslate2：**faster-whisper 使用独立后端；PyTorch CUDA 成功不能替代 CTranslate2 测试。
- **llama.cpp：**CPU 与 CUDA 发行包不同，部分 CUDA 包需要同时部署 cudart DLL。
- **显存：**本机 8GB 级别显存建议并发 1，按阶段加载模型；先测试 CPU 基线，再逐步增加 GPU 层数。

`scripts/verify_real_models.py --cuda --audio <真实人声音频>` 会分别记录 CPU/CUDA 的实际结果。模型加载失败会显示真实异常，不能把自动回退 CPU 写成 GPU 已通过。

## 4. 本地模型服务

```powershell
conda run --no-capture-output -n VideoLens python -m videolens.bootstrap runtime
conda run --no-capture-output -n VideoLens python -m videolens.bootstrap start-local --wait 240
conda run --no-capture-output -n VideoLens python -m videolens.bootstrap stop-local
```

日志在 `runtime/llama-server.log`。缺少 DLL 时先核对发行包和 VC++ 运行库。模型路径为空时先下载 `local` 模型；端口 8081 已被占用时，程序不会接管未知进程，可以修改 `local_base_url` 端口后重新启动。

有进程不等于模型已加载，`/health` 成功不等于已经生成过答案。真实 completion 测试应独立记录。首次 CPU 加载大模型可能较慢，适度增加 `--wait`，同时观察日志和内存。

## 5. 云端接口与问答

| 现象 | 检查项 |
|---|---|
| 没有调用云端 | 检查 `cloud_enabled`、对应 Provider 的 `enabled` 和模型名。 |
| 401/403 | 密钥或账号权限；重新写凭据库，检查引用名称是否一致。 |
| 404 | 核对 base URL 是否以 `/v1` 为接口根；检查供应商模型名。 |
| 429 | 服务限流/配额；等待后重试或降低并发，不能记录成已成功。 |
| 视觉报错 | 模型可能不支持图片或 `image_url`；文本模型成功不代表视觉也兼容。 |
| SSE 中断 | 需要完整结束标记；中途断线应显示失败或降级，不把半段文本存为完整答案。 |
| 答案“证据不足” | 先检索原始转录/帧，确认所问内容确实出现在视频。 |
| 总是基础摘录 | 查看文本云端与本地 llama 是否可用，以及结构化输出/引用校验失败原因。 |

## 6. 网页、任务与数据

端口 8000 被占用时先确认是否已经启动一份知影。不要重复双击造成多份任务执行；如需改端口，修改 `port` 并重启服务。API CLI 必须使用同一份配置，确保访问相同端口和令牌。

提示密码错误时读取当前 `data/.access-token`；修改 `data_dir` 或 `VIDEOLENS_API_TOKEN` 后，旧密码可能不再适用。云端 API Key 和网页登录密码是两种不同凭据。

任务暂停存在延迟时检查当前是否在不可分割的推理或媒体操作中。崩溃后重启会恢复中断任务；主动取消的任务需要用户重新提交，不会偷偷恢复。

媒体过期后无法播放但报告仍存在，这是媒体保留策略的结果。需要重新提供原视频，或提前增加保留天数。删除视频前确认选中 ID；原始视频不属于受管目录，自动清理不会删除它。

如果索引损坏但转录和帧仍在，使用“重建索引”。如果 SQLite 本身损坏，应停止程序并恢复备份；重新建 Chroma 不能恢复丢失的 SQLite 业务记录。
