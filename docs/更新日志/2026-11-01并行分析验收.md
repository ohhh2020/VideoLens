## 标准视频真实对比

视频：[E5 2696v3 对比 R5 5600(XT)](https://www.bilibili.com/video/BV1rkxi66Ej2)，时长 **686.544秒（11分26秒）**，实际 **1920×1080**，每轮 **70帧、36个切片**。

Windows、Core Ultra 7 255H、RTX 5060 Laptop GPU；同一Conda Python 3.13环境，Whisper small、BGE-M3和SigLIP2实际设备均为CUDA，文本和视觉复用已配置云端模型。通过用户的可见Git Bash控制台正常重启服务，没有另建隐藏服务。

计时从网页内部消息提交开始，到分析、发布及会话标题操作完成为止，包含每轮重新下载，不含服务启动和权重加载。新分析使用 `force=true`，不是报告缓存命中。监测间隔2秒，总时间可能有约2秒观察误差。测量期间未并行运行回归测试。

## 信息覆盖与验收边界

最终轮在241个完整单元中选择73个、遗漏168个，关联36/36个切片；原始证据192条仍保留。紧凑报告轮为77/244个单元；不同轮次云端OCR结果有所变化。**36/36只表示每个切片有单元入选，绝不是所有事实召回率100%。** 超预算的长句不会截尾塞入，可能整条不入选；原文及遗漏状态可查。

定点复核三项核心比较方向：5600XT生产力为E5的88%（落后12%）、网游为132%（领先32%）、单机3A为105%（领先5%）。最终报告的CPU-Z和R23表格保留了以E5为基准的降低方向；但结论仍将口播“81%劣势”与画面“70.4%领先”并写，冲突解释未完全消除。全部配置、型号、跑分、字幕与OCR冲突并未逐条人工校验，未做人工标注的90%事实召回评测。模型仍可能误述来源中的比较基准，因此报告不能替代原始画面核对。

本轮通过真实媒体与模型替身回归验证完整单元、超长遗漏、OCR全部时间映射、同名字幕、参数缓存失效、共享删除、实际帧时间/旋转/起始偏移、视觉流式启动与失败缓存、总结索引重叠以及HTTP状态/NO_PROXY/SSE。全套后端42组通过，前端10组JSDOM通过；当时新增优化用例12项通过。真实云端结果和模拟回归分别记录，没有把JSDOM当作真实浏览器视觉验收。

## 复现和备份

在已启动且没有任务的服务下执行（会真实下载、创建会话并调用云端）：

```bash
python scripts/benchmark_web.py --source "https://www.bilibili.com/video/BV1rkxi66Ej2" --no-transcript-cache --output "../VideoLens-runtime/tests/fast-v4/repeat.json"
```

去掉 `--no-transcript-cache` 才允许内容转写缓存。普通网页重复提交已完成视频会直接复用报告，这与强制重跑且复用转写是不同情况。

实施前备份位于 `VideoLens-runtime/backups/before-fast-v4-20261101-033655/`，包含源码快照、数据库和原始用户视频/会话ID。旧视频不批量升级，失败的新分析不覆盖旧报告；该次性能测试结束时尚未推送；后续发布见[版本记录](版本记录.md)。

最终报告可在[标准视频测试会话](http://127.0.0.1:8000/ui?conversation=ca89438171a654139bc59fdadb4f707a0)查看。其余4条测试会话已先归档到 `tests/fast-v4/test-conversations-archive.json` 再单独清理，没有触发业务的联动删视频。原来的2个视频和2个会话均核验保留；当前另留1个标准测试视频及其最终会话。
