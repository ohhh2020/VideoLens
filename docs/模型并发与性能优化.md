# 模型并发与性能优化

## 分阶段并行

场景检测与音频提取、语音转写并行。当前 fast-v3 固定间隔抽帧，整帧概述与OCR合并为批量请求；完成证据索引后一次生成报告。不做局部加密、原像素裁图或分层章节摘要。云端网络请求不占用本地推理锁。

同一视频使用视频级锁，后来的请求等待当前任务完成，再复用缓存或断点恢复，避免重复全量处理。已经与转写并行计算的场景结果会直接复用。

## 模型边界

BGE 与 SigLIP 各有模型锁，同一编码器不接受无界并发。共享同一张 GPU 的本地推理受 GPU 边界约束，控制显存峰值。Whisper 按 VAD 音频块批量处理，同引擎的转写请求排队。

默认保留启动预热后的权重，避免第一次分析或提问再次加载。GPU 向量编码使用 FP16 与批量上限，CPU 保留 FP32。

云端视觉按时间顺序合并多帧，超出每组帧上限时继续分组，保留需要处理的帧。长视频场景检测可使用 FFmpeg/NVDEC 与低分辨率评分；关键帧去重减少重复画面请求。抽帧限制单进程线程数，避免多个 FFmpeg 进程争抢全部 CPU。

## 可配置项

| 参数 | 用途 |
| --- | --- |
| `models.keep_loaded` | 保留已验证权重 |
| `models.cpu_threads` | PyTorch CPU 线程 |
| `asr.cpu_threads`、`asr.batch_size` | Whisper 线程和音频块批量 |
| `embedding.gpu_batch_size` | GPU 向量批量上限 |
| `vl.cloud_workers` | 云端视觉并发上限 |
| `vl.cloud_sequence_frames` | 每轮视觉采样帧上限 |
| `media.scene_detect.ffmpeg_threads` | 抽帧线程数 |
| `llm.cloud.max_concurrency` | 云端文本请求并发上限 |
| `qa.query_rewrite_mode` | 默认利用会话主题补全检索问题，也可选云端改写 |

参数位于 `configs/app_config.yaml`。线程数更大不一定更快，须同时考虑显存、CPU、网络与服务商限流。

## 索引与交互

新索引完整写入且报告验证成功后才事务切换活动版本；失败保留旧索引和旧报告，以及可手动重试的独立运行目录。已完成视频普通提交直接复用原结果，配置变化不会自动重算。首次分析、手动恢复与缓存复用耗时分别记录。

问答先推送处理状态，再执行 BGE 文本、SigLIP 跨模态与 BM25 检索，用 RRF 合并证据，流式生成答案。BM25 按切片变化更新缓存，默认会话主题改写不额外调用云端。

偏好归纳在后台单线程队列运行，不阻塞本轮结果，编码复用 BGE 与既有设备锁，不部署第四个本地模型。

不要只凭 `nvidia-smi` 瞬时利用率判断模型设备，应结合实际设备与阶段日志。真实测量见[10 分钟视频性能测试](10分钟视频性能测试.md)。

## 当前统一调度

网页“分析质量与资源”的 `integrity` 参数优先控制新任务：GPU 初始 batch 为 4，BGE/SigLIP 上限 16，Whisper 上限 8；根据空闲显存及测得峰值调整，OOM 逐次减半至 1，仍失败就报错，不自动换 CPU 或哈希编码。

云端总在途默认 8、文本 4、视觉 8。交互问答优先，后台请求通过等待老化维持公平；429 和临时故障最多重试 3 次并尊重 Retry-After。任务快照、证据与提示词版本共同确定缓存，只补未完成请求；服务重启不自动重新调用云端。

旧 integrity-v2 增加的章节摘要、局部加密采样和高清裁图OCR已回退。当前以减少必要请求之外的工作量提升效率，保留动态问答和原始证据。未配置价格时仅统计请求与tokens。最新实测见[回退与效率验收](回退与效率验收.md)。
