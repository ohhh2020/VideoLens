## 2. 真实语音与图文模型结果

ASR 使用 faster-whisper 1.2.1、CTranslate2 4.8.3，模型固定版本见模型清单。以下计时来自各次实际调用，包含模型加载与缓存冷热差异，不适合直接比较 CPU/CUDA 速度倍数。

| 路径与样本 | 实际设备 | 误差 | 本次耗时 |
|---|---|---|---|
| 中文 FunASR，CPU 首次测试 | CPU | CER 2/19 = **10.53%** | 6.817 秒 |
| 英文 JFK，CPU 测试 | CPU | WER 0/22 = **0%** | 5.724 秒 |
| 中文 FunASR，产品 auto 路径 | CUDA | CER 2/19 = **10.53%** | 11.171 秒 |
| 英文 JFK，同一产品网关 | CUDA | WER 0/22 = **0%** | 0.443 秒 |

中文识别将“达摩院”识别为“打磨院”，这两个字的替换真实计入 CER，没有手工改成正确答案。英文按大小写与标点归一后统计 22 个参考单词。片段时间检查覆盖音频范围，没有人工逐词时间标注，因此不宣称时间对齐误差达到某个毫秒指标。

SigLIP2 使用两张本地生成的图：白底红色正方形、白底蓝色圆形。真实产品网关生成 `2×768` 图像向量和 `4×768` 文本向量，中文与英文四条查询 Top-1 全部正确，向量均为有限数且范数接近 1。图片编码含加载 50.224 秒，四条文本查询 0.685 秒；这是功能冒烟与简单语义区分结果，不能代替真实视频检索数据集评估。原始分数见 `data/verification/siglip2-real.json`。

四类本地模型的完整 CPU 验证记录在 `data/verification/real-models.json`：ASR 7.364 秒、BGE-M3 18.622 秒、SigLIP2 5.425 秒、本地 llama 启动与生成 6.131 秒，四项均通过。BGE 使用两条牛顿第二定律相关句与一条烹饪无关句，相关语义排序正确；llama 返回“测试成功”，`prompt_tokens=20`、`completion_tokens=3`、`gpu_layers=0`。上述是一次实际运行的耗时，不能当成稳定延迟基准。

CUDA 本地生成另行验证：官方运行时 SHA 校验通过，模型实际卸载 37/37 层到 RTX 5060，真实短回答生成 0.141 秒。默认日志没有输出层卸载信息，首次验收因此拒绝判定成功；随后使用运行时公开的日志级别 4 重新验证，才确认 GPU 路径。日志记录模型缓冲约 2375.91MiB、KV 缓冲 1152MiB、计算缓冲 85.01MiB；这些是 llama 运行时报告的分配量，不等于整机峰值显存。当前本机配置已启用 CUDA llama，CPU 运行时仍保留；向量模型继续使用已验证的 PyTorch CPU 路径。

## 3. 完整流水线和性能差距

下面都是实际输入与实际模型，没有 Mock。短样本和一小时样本内容相同，使用已知字幕并重复章节内容；不包含真实长音频 ASR 和云端视觉。由于未配置云端视觉，分析任务最终状态为 `partial`，报告和问答生成方式均为 `generated`。这个状态正确表达了视觉通道降级，不是把基础摘录当作模型生成。

| 测量项 | 40 秒，CPU 全本地 | 3600 秒，CPU 全本地 | 40 秒，向量 CPU + llama CUDA，最终代码 |
|---|---:|---:|---:|
| 整轮分析、检索、问答、导出、重启读取 | 106.107 秒 | 710.28 秒 | 66.388 秒 |
| 切片 / 关键帧 / 章节数 | 2 / 2 / 1 | 180 / 180 / 12 | 2 / 2 / 1 |
| 本地模型启动健康检查 | 3.284 秒 | 3.731 秒 | 2.672 秒 |
| 问答首事件，包含检索 | 10.582 秒 | 11.076 秒 | 10.466 秒 |
| 进入生成阶段到首模型 Token | 5.794 秒 | 32.522 秒 | 0.471 秒 |
| 一次问答总耗时，包含检索 | 27.166 秒 | 61.627 秒 | 12.028 秒 |
| 流程进程树 RSS 峰值 | 7.67GiB | 10.50GiB | 5.21GiB |

进程树 RSS 通过 psutil 每 0.2 秒采样当前验证进程与子进程，不包含整机其他程序；不同运行间的系统缓存、负载也不同，表中不能直接推导稳定加速倍数。一小时样本的实际阶段耗时为：探测 0.159 秒、字幕解析 0.015 秒、抽帧 30.663 秒、双向量索引 112.892 秒、章节和总报告生成 485.099 秒。样本有字幕，未执行一小时音频提取与 ASR，因此没有冒充完成该项性能验收。

对照原始需求：

- **启动 ≤5 秒未达到**：一键入口含环境冒烟、网页后端健康检查实测 11.753 秒；没有单独建立 OS 冷缓存/暖缓存的重复启动统计。
- **首次响应 ≤10 秒未达到本轮目标**：最终问答首状态事件 10.466 秒。**从问题提交到首 Token ≤3 秒也未达到**：还需先完成约 10.466 秒检索；不能用单独生成阶段的 0.471 秒冒充端到端首 Token。
- **中文 CER≤15%、英文 WER≤20%**：本次两个短样本达到，但不证明其他口音、噪声、领域或长视频普遍达标。人工时间对齐误差尚未建立标准集，不能判定 ≤1 秒达标。
- **引用证据**：后端对返回结论执行有效 ID 和原文检查；已知合成样例的核心回答“自动字幕和会议记录”有对应字幕支持。一小时总结存在重复表述，真实复杂问答的人工支持率尚未形成统计。
- **关键帧**：合成样例保留原生 1280×720，大小低于 200KB；低分辨率样例保留实际 640×360 并标注降级。FFmpeg 场景样例验证 2 秒切换点误差小于 110ms，不等于所有视频帧都达到同一误差。
- **最低 8GB 内存与界面 ≤200ms**：本机约 32GB，完整 CPU 一小时样例进程树达到 10.50GiB；没有在 8GB 限制环境验收，也未完成前端每项操作的稳定延迟基准。

最终短样例的实际原始结果在 `data/verification/pipeline-final.json`，CPU 长样例在 `one-hour.json`，导出的 Markdown 与 JSON 同目录保存。验证过程中使用 `models/model-manifest.json` 固定各模型 revision 和文件 SHA。

## 4. 环境与安装问题

本机 `VideoLens` 环境使用 Python 3.13.16。现有环境被保留，依赖以实际 pip 安装清单为准。CPU 基线和 GPU 路径分开验证。

安装前备份保存在 `environment-backups/before-install.yml`，Conda 异常恢复时记录的包元数据在同目录 `recovered-packages.json`。安装后另导出 `data/environment-backups/after-install-20261014.yml` 与 `requirements-installed.txt`。两类快照按真实阶段区分，没有把安装后清单冒充安装前备份；这些本机环境文件均被 Git 忽略。

`requirements-lock.txt` 保存当前实际环境的 135 个锁定依赖，已删除 editable 安装绝对路径；基线明确为 Windows x64、Python 3.13.16、PyTorch CPU。主验证执行 `pip check` 未发现损坏依赖。

Conda-forge FFmpeg 安装曾在 gdk-pixbuf post-link 阶段遇到 DLL/编码错误并回滚；没有将该失败视为安装通过。现已使用 FFmpeg 官网推荐的 Gyan 8.1.2 固定 ZIP 回退，官方 SHA-256 校验通过，实际 FFmpeg 和 FFprobe 运行通过。配置脚本保留此回退路径，避免重复执行失败的 Conda 事务。

沙箱内的 `conda.exe` 曾因系统 DLL 重定位拒绝启动，环境测试改为直接使用同一 `VideoLens` 环境中的 Python，成功完成冒烟和辅助测试。这个现象属于当前受限执行环境，不能据此认定普通用户终端中的 Miniconda 已损坏。

## 6. 已修复问题与待外部条件验收

每个真实模型结果需记录模型版本、设备、输入、耗时和实际输出。GPU 测试必须标明实际执行后端；回退 CPU 后成功只能算 CPU 流程成功。

完整流程应覆盖：配置与启动 → 导入 → 后台分析 → 原始证据 → 同一视频多轮追问 → Markdown/JSON 导出 → 重启读取历史。模型不可用时应验证降级提示准确；关键阶段不可继续时应保持失败状态。

时间指标区分任务阶段耗时、首个 SSE 事件、首个模型 Token 和完整回答耗时。状态提示事件不能冒充模型首 Token。内存与显存记录需要注明采样方法；进程 RSS 和系统物理内存不是同一个指标。

已修复并回归覆盖：PyAV 19 音频解码接口变更、CTranslate2 与 PyTorch CUDA 判定混淆、BGE 下载缺少实际权重、Gradio 6 登录媒体校验、流式生成器跨线程锁释放、未知时长 HTTP 直链被 yt-dlp 过滤、同视频暂停任务重复创建、失败重分析破坏旧代证据、索引部分失败、丢失检查点文件恢复、历史摘要被挤掉、生成预算超窗、章节摘要未实际进入最终上下文、旧代图片清理、模型 revision 变化和配置 JSON 往返造成指纹不稳定、二次保存覆盖待重启配置，以及修改本地模型启动参数未提示重启。

待外部条件验收：有效云端文本/视觉/OCR、各外部视频平台、8GB 受限内存环境、完整人工标注问答和时间对齐数据集、真实一小时人声转写、浏览器上述最后两项复验、Linux 后端。当前没有将这些项目写成通过。现有自动化中的唯一警告是 Starlette 提示未来迁移 httpx2，不影响本次 84 项断言结果。
