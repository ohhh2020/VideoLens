# 自动问答修复与发布验收

日期：2026-11-01。对应版本快照：`2026-11-1-lts`。

## 问题与原因

输入“【【26年11月CPU推荐】分享标题】视频链接 + 为什么这些cpu会出现历史最低点”时，只生成报告，没有单独回答问题。

真实数据库显示：原始用户消息包含完整问题，分析操作状态为已完成，但决策落库的 `question` 为空。后端因此进入完成阶段，未进入问答阶段，并非网页隐藏了已生成回答。

原来的显式问题保护主要识别“然后/分析完成后”等连接词，或整条消息开头的“为什么/如何”等词。分享标题位于开头时会漏匹配；智能层此次同样返回了空问题。另一个本地视频请求“帮我罗列视频中出现的cpu和推荐指数”也因指令词未覆盖而被漏掉。

## 修复行为

1. 程序先提取真实HTTP/HTTPS候选，正确处理Markdown标签、目标地址与去重。
2. 分离紧邻来源之前的分享标题，支持嵌套【标题】、书名号及Markdown链接；标题里的问句不会触发额外问答。
3. 保护链接前后、换行或本地附件消息中的明确问题，以及罗列、整理、比较、解释等要求，不再依赖“然后”。保留问题中的预算和比较条件。
4. 将分离后的正文同时提供给智能层。模型选择来源仍只能引用实际候选编号，不能构造新路径或地址。
5. 多来源先澄清，选择后保留原问题；2000字符限制继续校验。只要求分析或总结时不额外触发问答。
6. 报告先落库，再执行独立问答；分析失败停止后续问答，问答失败保留报告并只重试问答。幂等请求不重复生成内容。

真实补答时还复现了“问答证据压缩未收敛”：应用输入估算使用UTF-8字节，而旧压缩步骤仅设置服务商token上限，模型可能把短证据扩写为更长的回答。现已为每批证据提炼设置正文字符约束和实际字节校验；超长或截断时使用更紧限制重试一次，不对压缩结果续写扩张，不裁切原始证据。原始问题和实际编号继续用于最终回答。
