# 记忆库

工作台的“记忆库”页签可以查看、增加、修改或删除偏好。每条记录是一段精简完整的话，例如“用户近期更关注本地 AI 部署的硬件需求与实际性能”。修改后会同步重新计算向量，无需重启。

## 自动归纳与使用

启动后会在后台检查已有的成功视频分析和用户提问；新的分析或问答完成后也会触发增量检查。使用当前配置的云端文本模型提炼偏好，用已有 BGE-M3 转为向量，不增加本地模型。历史归纳失败会在记忆库显示状态，不编造记忆；已有记忆仍可用。

自动记忆仅描述视频兴趣、问题关注点和明确表达的回答风格。兴趣至少需要两条历史依据，直接表达的个人偏好可使用一条提问依据。不会把单次观看直接当成明确喜好，也不把视频观点或生成答案的风格当成用户自己的态度。每次检查记录已处理来源，重复查看、缓存复用和服务重启不会重复学习同一批历史。

后续生成视频总结、章节摘要、综合总结和问答时，会检索相关记忆作为关注点与表达参考。视频报告的所有记忆（包括“回答风格”）都必须通过与本片证据的相关性筛选，默认相似度门槛为 `memory.report_min_similarity=0.55`；召回查询只取视频标题和原始证据，不包含总结格式要求。普通问答继续允许通用回答风格作为表达参考。

无关偏好必须静默忽略，报告不得评价偏好、解释记忆是否适用，也不得为了回应偏好而罗列与本视频无关的话题。手动记忆优先，当前问题与视频证据优先。记忆不作为视频引用，不改变视频事实，也不替换报告的完整结构。历史报告不会因新增记忆自动改写。

历史归纳在独立的单线程后台队列运行，前台不用等待它完成才收到本轮总结或回答。归纳期间的 BGE-M3 编码与其他本地任务共用模型锁和 GPU 边界。退出服务时先等待记忆任务收尾，再释放模型和数据库。

## 用户控制

- “在总结和对话中使用记忆”：即时控制后续生成是否检索偏好，关闭后保留现有数据。
- “从历史自动归纳”：即时控制后台学习；关闭后仍可手动增加和编辑。
- “从历史更新”：检查未处理的历史，证据不足时可以不增加任何记录。
- “保存修改”：文字和向量一起更新，并将该条记忆标为手动记忆。
- “删除记忆”：同时移除文段和向量，只保留不可逆摘要与已处理历史标识，防止同一历史反复生成刚删除的记忆。新的历史仍可形成新记忆。

正在归纳时发生手动编辑或删除，会丢弃此前开始的那批自动结果，避免覆盖用户操作。编辑中的草稿不会被后台状态刷新覆盖。删除对后续检索生效，已经完成的历史回答和报告保留原文。

## 本地文件

默认位置：

```text
D:/Project/vl/VideoLens-runtime/data/memory/preferences.json
```

跟随 `VIDEOLENS_RUNTIME_ROOT`。文件是可阅读的 UTF-8 JSON，包含：

| 字段 | 内容 |
|---|---|
| `items[].id` | 稳定的记忆编号 |
| `items[].text` | 用户可读的偏好文段 |
| `items[].vector` | 对应的 BGE-M3 1024 维归一化向量 |
| `items[].kind` | 视频兴趣、问题关注点或回答风格 |
| `items[].origin` | 手动编辑或历史归纳 |
| `items[].evidence` | 历史依据标识及简短标签 |
| `enabled` / `auto_learn` | 使用与自动学习开关 |
| `seen_sources` / `blocked_hashes` | 已处理历史标识与已删除文字的不可逆摘要 |

每次修改先写临时文件，再原子替换；保存失败时保留旧数据。网页只展示文段与来源，不输出整组向量。请通过网页编辑文字，使文字与向量同步更新。

`configs/app_config.yaml` 的 `memory` 段可配置文件位置、容量、每段字数、召回数量和相似度阈值。默认最多 200 条，每条最多 220 字，每次生成最多召回 4 条。代码、Conda 依赖、运行数据保持分离。
